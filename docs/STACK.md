# Philos Tech Stack Guide

How the pieces fit together when migrating from Supabase to **Next.js + SQL Server**.

| Layer | Tool |
|-------|------|
| Frontend (current) | Vite + React + TanStack Query + **axios** |
| Backend | Next.js App Router (`app/api/v1/`) |
| ORM | **Drizzle** |
| Database | SQL Server |
| Validation | Zod (shared between API routes and forms) |
| Auth | Auth.js v5 **or** custom JWT *(see [Auth comparison](#auth-authjs-v5-vs-custom-jwt) below)* |

Related docs:
- [`database/schema.sql`](../database/schema.sql) — raw SQL schema
- [`docs/API.md`](./API.md) — REST endpoint reference

## Architecture

```
┌─────────────────────────────────────────────────────────┐
│  Vite React SPA                                         │
│  ├── TanStack Query  (server state, cache, mutations)   │
│  ├── axios instance    (HTTP client → /api/v1)          │
│  └── Redux             (locale, pagination only)        │
└──────────────────────────┬──────────────────────────────┘

                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│  SQL Server                                             │
└─────────────────────────────────────────────────────────┘
```

## Drizzle (backend ORM)

Drizzle replaces direct Supabase queries. Each API route imports a shared `db` client and runs type-safe queries.

### Packages (Next.js backend)

```bash
npm install drizzle-orm mssql
npm install -D drizzle-kit
```

### Folder structure

```
server/                        # or inside Next.js project root
├── db/
│   ├── index.ts               # db client (connection pool)
│   ├── schema/
│   │   ├── users.ts
│   │   ├── philosophers.ts
│   │   ├── articles.ts
│   │   └── index.ts           # re-export all tables
│   └── migrations/            # generated by drizzle-kit
├── lib/
│   ├── auth.ts                # getSession(), requireAuth()
│   └── validators/              # Zod schemas per resource
└── app/api/v1/...             # route handlers call Drizzle
```

### Example schema (maps to `database/schema.sql`)

```ts
// server/db/schema/users.ts
import { sql } from 'drizzle-orm';
import {
  int, bit, datetime2, nvarchar, uniqueIndex,
  mssqlTable, primaryKey,
} from 'drizzle-orm/mssql-core';

export const users = mssqlTable('Users', {
  id: nvarchar('Id', { length: 36 }).primaryKey().default(sql`NEWID()`),
  email: nvarchar('Email', { length: 320 }).notNull(),
  passwordHash: nvarchar('PasswordHash', { length: 255 }).notNull(),
  emailConfirmed: bit('EmailConfirmed').notNull().default(false),
  phone: nvarchar('Phone', { length: 20 }),
  createdAt: datetime2('CreatedAt').notNull().default(sql`SYSUTCDATETIME()`),
  updatedAt: datetime2('UpdatedAt').notNull().default(sql`SYSUTCDATETIME()`),
}, (t) => [uniqueIndex('UQ_Users_Email').on(t.email)]);

export const profiles = mssqlTable('Profiles', {
  id: nvarchar('Id', { length: 36 }).primaryKey(),
  username: nvarchar('Username', { length: 50 }).notNull(),
  fullName: nvarchar('FullName', { length: 200 }),
  bio: nvarchar('Bio', { length: 'max' }),
  avatarUrl: nvarchar('AvatarUrl', { length: 500 }),
  articlesCount: int('ArticlesCount').notNull().default(0),
  // ...
});
```

### Example query in a route handler

```ts
// app/api/v1/articles/route.ts
import { db } from '@/server/db';
import { articles, profiles, articleReactionCounts } from '@/server/db/schema';
import { eq } from 'drizzle-orm';

export async function GET() {
  const rows = await db
    .select({
      id: articles.id,
      title: articles.title,
      authorUsername: profiles.username,
      likes: articleReactionCounts.likes,
    })
    .from(articles)
    .leftJoin(profiles, eq(articles.authorId, profiles.id))
    .leftJoin(articleReactionCounts, eq(articles.id, articleReactionCounts.articleId))
    .where(eq(articles.state, 'published'));

  return Response.json({ data: rows });
}
```

### Drizzle vs raw SQL

| Use Drizzle for | Keep raw SQL / triggers for |
|-----------------|----------------------------|
| CRUD in API routes | `TR_Users_AfterInsert` (auto profile) |
| Joins, filters, pagination | `ArticleReactionCounts` view |
| Type-safe inserts/updates | Complex reporting queries |

## axios (frontend HTTP client)

Replace every `supabase.from(...)` call with axios requests to `/api/v1`.

### Setup

```ts
// src/lib/api/client.ts
import axios from 'axios';

export const api = axios.create({
  baseURL: import.meta.env.VITE_API_URL ?? 'http://localhost:3000/api/v1',
  withCredentials: true,   // sends httpOnly session cookie
  headers: { 'Content-Type': 'application/json' },
});

// Attach Bearer token if stored (optional fallback)
api.interceptors.request.use((config) => {
  const token = localStorage.getItem('accessToken');
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

// Global 401 handling
api.interceptors.response.use(
  (res) => res,
  (error) => {
    if (error.response?.status === 401) {
      // redirect to login or clear session
    }
    return Promise.reject(error);
  }
);
```

### Service layer (replaces Supabase services)

```ts
// src/modules/articles/services/articleApi.ts
import { api } from '@/lib/api/client';

export const articleApi = {
  getAll: () => api.get('/articles').then((r) => r.data),
  getById: (id: string) => api.get(`/articles/${id}`).then((r) => r.data),
  create: (body: CreateArticleDto) => api.post('/articles', body).then((r) => r.data),
  getReactions: (id: string) => api.get(`/articles/${id}/reactions`).then((r) => r.data),
  react: (id: string, reaction: 'like' | 'dislike') =>
    api.put(`/articles/${id}/reactions`, { reaction }).then((r) => r.data),
};
```

## TanStack Query + axios

You already use TanStack Query. Keep the same pattern — only swap `queryFn` / `mutationFn` from Supabase to axios.

### Before (Supabase)

```ts
const getArticles = async () => {
  const { data, error } = await supabase.from('articles').select('...');
  if (error) throw error;
  return data;
};

export const useArticles = () =>
  useQuery({ queryKey: ['articles'], queryFn: getArticles });
```

### After (axios + TanStack Query)

```ts
import { articleApi } from '../services/articleApi';

export const useArticles = () =>
  useQuery({
    queryKey: ['articles'],
    queryFn: () => articleApi.getAll(),
    select: (res) => res.data,   // unwrap { data: [...] }
  });

export const useCreateArticle = () => {
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: articleApi.create,
    onSuccess: () => queryClient.invalidateQueries({ queryKey: ['articles'] }),
  });
};
```

### Query key conventions

| Resource | Query key |
|----------|-----------|
| Articles list | `['articles']` |
| Single article | `['articles', id]` |
| Comments | `['comments', articleId]` |
| Reaction counts | `['article_reaction_counts', articleId]` |
| Philosophers page | `['philosophers', page, filters]` |
| Philosopher bio | `['philosopherBio', id]` |
| Profile | `['profile', userId]` |
| Session | `['session']` |

### Auth session with TanStack Query

```ts
// src/modules/auth/hooks/useSession.ts
export const useSession = () =>
  useQuery({
    queryKey: ['session'],
    queryFn: () => api.get('/auth/session').then((r) => r.data),
    retry: false,
    staleTime: 5 * 60 * 1000,
  });
```

Use `useSession()` in `ProtectedRoute` instead of `supabase.auth.onAuthStateChange`.

## Auth: Auth.js v5 vs Custom JWT

Both approaches work with Drizzle + SQL Server. The choice depends on how much auth logic you want the framework to own.

---

### Option A — Auth.js v5 (Credentials + Drizzle adapter)

**What it is:** A full authentication library for Next.js. You configure providers and it handles sessions, cookies, and callbacks.

**How Credentials provider works:**

```ts
// auth.ts
import NextAuth from 'next-auth';
import Credentials from 'next-auth/providers/credentials';
import { DrizzleAdapter } from '@auth/drizzle-adapter';
import { db } from './db';
import bcrypt from 'bcryptjs';

export const { handlers, auth, signIn, signOut } = NextAuth({
  adapter: DrizzleAdapter(db),          // optional: DB-backed sessions/accounts
  session: { strategy: 'jwt' },          // or 'database' with adapter
  providers: [
    Credentials({
      credentials: { email: {}, password: {} },
      async authorize(credentials) {
        const user = await db.query.users.findFirst({
          where: eq(users.email, credentials.email),
        });
        if (!user) return null;

        const valid = await bcrypt.compare(credentials.password, user.passwordHash);
        if (!valid) return null;

        return { id: user.id, email: user.email, name: user.username };
      },
    }),
  ],
});
```

**Routes:** Auth.js owns `/api/auth/*` (not `/api/v1/auth/*`):

```
POST /api/auth/callback/credentials   → login
POST /api/auth/signout                → logout
GET  /api/auth/session                → current session
```

**Drizzle adapter** stores `User`, `Account`, `Session`, `VerificationToken` tables (Auth.js schema). You can extend or map these to your existing `Users` / `Profiles` tables.

| Pros | Cons |
|------|------|
| Battle-tested session/cookie handling | Routes are `/api/auth/*`, not your `/api/v1/auth/*` doc |
| Built-in CSRF protection | Credentials provider needs careful setup (no OAuth magic) |
| `auth()` helper in Server Components & API routes | Vite SPA must call Auth.js endpoints (not standard REST shape) |
| Drizzle adapter for DB sessions | Password reset / email confirm still custom |
| Less auth boilerplate | Learning curve; v5 API differs from v4 |

**Best when:** You move the frontend into Next.js (or keep Vite but accept Auth.js route conventions), and you want the framework to manage sessions.

**Vite SPA + Auth.js:** Frontend calls `signIn` via `next-auth/react` only works inside Next.js. For a separate Vite app, POST credentials to `/api/auth/callback/credentials` with CSRF token, or use a thin wrapper endpoint.

### Option B — Custom JWT (your documented `/api/v1/auth/*`)

**What it is:** You write auth endpoints yourself. Login verifies password with bcrypt, issues a JWT, stores refresh token in `RefreshTokens` table.

**Flow:**

```
1. POST /api/v1/auth/login  → verify password (Drizzle query)
                           → sign JWT (jose or jsonwebtoken)
                           → Set-Cookie: session=<jwt>; HttpOnly
                           → optionally return accessToken in body

2. GET /api/v1/auth/session → decode JWT from cookie/header
                            → return user + profile (Drizzle join)

3. Protected routes → middleware reads JWT, attaches userId to request

4. POST /api/v1/auth/logout → clear cookie, revoke refresh token
```

**Example login route:**

```ts
// app/api/v1/auth/login/route.ts
import { SignJWT } from 'jose';
import bcrypt from 'bcryptjs';
import { db } from '@/server/db';
import { users, profiles } from '@/server/db/schema';
import { eq } from 'drizzle-orm';

export async function POST(req: Request) {
  const { email, password } = await req.json();

  const user = await db.query.users.findFirst({ where: eq(users.email, email) });
  if (!user || !(await bcrypt.compare(password, user.passwordHash))) {
    return Response.json({ error: { code: 'UNAUTHORIZED', message: 'Invalid credentials' } }, { status: 401 });
  }

  const token = await new SignJWT({ sub: user.id, email: user.email })
    .setProtectedHeader({ alg: 'HS256' })
    .setExpirationTime('7d')
    .sign(new TextEncoder().encode(process.env.JWT_SECRET!));

  const res = Response.json({ data: { user: { id: user.id, email: user.email } } });
  res.headers.set('Set-Cookie', `session=${token}; HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=604800`);
  return res;
}
```

**Auth middleware for protected routes:**

```ts
// server/lib/auth.ts
import { jwtVerify } from 'jose';
import { cookies } from 'next/headers';

export async function requireAuth() {
  const token = (await cookies()).get('session')?.value;
  if (!token) throw new AuthError('UNAUTHORIZED');

  const { payload } = await jwtVerify(token, new TextEncoder().encode(process.env.JWT_SECRET!));
  return { userId: payload.sub as string };
}
```

| Pros | Cons |
|------|------|
| Matches [`docs/API.md`](./API.md) exactly (`/api/v1/auth/*`) | You own all security details |
| Natural fit for Vite SPA + axios + TanStack Query | Must implement refresh tokens, reset password, etc. |
| Full control over response shape | Easy to get wrong (token expiry, cookie flags) |
| Same REST style as philosophers/articles endpoints | No built-in CSRF (mitigate with SameSite cookies) |
| Works with `withCredentials: true` on axios | |

**Best when:** You keep the Vite SPA, use axios for everything, and want one consistent `/api/v1` REST API.

### Side-by-side comparison

| Topic | Auth.js v5 + Credentials | Custom JWT |
|-------|--------------------------|------------|
| Login endpoint | `/api/auth/callback/credentials` | `POST /api/v1/auth/login` |
| Session check | `GET /api/auth/session` or `auth()` | `GET /api/v1/auth/session` |
| Vite + axios | Awkward (different route shape) | Natural fit |
| Drizzle usage | Queries in `authorize()` + adapter tables | Queries in each auth route |
| Password reset | Custom routes anyway | Custom routes (already in API doc) |
| DB tables | Auth.js tables + yours | Your `Users`, `RefreshTokens`, etc. |
| Session storage | JWT or DB via adapter | JWT in cookie + optional `RefreshTokens` |
| Protected API routes | `const session = await auth()` | `const { userId } = await requireAuth()` |
| Complexity | Lower for auth, higher for SPA integration | Higher for auth, lower for SPA integration |

### Recommendation for Philos

```
┌────────────────────────────────────────────────────────────┐
│  Recommended: Custom JWT + /api/v1/auth/*                  │
│                                                            │
│  Why:                                                      │
│  • Vite SPA already uses TanStack Query (not Next.js RSC)  │
│  • axios maps cleanly to documented REST endpoints         │
│  • Same pattern for auth, articles, philosophers           │
│  • Drizzle handles all DB access in route handlers         │
└────────────────────────────────────────────────────────────┘
```

Choose **Auth.js** instead if you later:
- Move the whole app into Next.js (App Router pages)
- Want OAuth providers (Google, GitHub) with minimal setup
- Prefer `auth()` over writing JWT middleware

You can also **hybrid**: Auth.js for login/session + `/api/v1/*` for data, but that splits auth across two systems and is usually not worth it.

## Migration checklist

### Backend (Next.js + Drizzle)

- [ ] Init Drizzle with SQL Server connection string
- [ ] Define Drizzle schema matching `database/schema.sql`
- [ ] Run migrations (`drizzle-kit push` or `migrate`)
- [ ] Implement `/api/v1/auth/*` (custom JWT recommended)
- [ ] Add `requireAuth()` middleware
- [ ] Implement data routes (philosophers, articles, comments, …)
- [ ] Share Zod schemas with frontend where possible

### Frontend (Vite + axios + TanStack Query)

- [ ] `npm install axios`
- [ ] Create `src/lib/api/client.ts`
- [ ] Create service files per module (`articleApi`, `philosopherApi`, `authApi`)
- [ ] Replace Supabase calls in hooks with axios services
- [ ] Replace `useAuth` / `ProtectedRoute` with `useSession` query
- [ ] Remove `@supabase/supabase-js` when migration is complete
- [ ] Set `VITE_API_URL` in `.env`

### Env variables

```env
# Frontend (.env)
VITE_API_URL=http://localhost:3000/api/v1

# Backend (.env)
DATABASE_URL=Server=localhost;Database=Philos;User Id=...;Password=...;Encrypt=true
JWT_SECRET=your-long-random-secret
JWT_EXPIRES_IN=7d
```
